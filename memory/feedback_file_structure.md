# Правила работы с файловой структурой

**Проблема:** Я перепутал назначение файлов (spec vs report), создал лишние файлы, не проверил текущее состояние перед действиями.

**Почему:** Не прочитал файлы перед тем как делать предположения об их содержимом и назначении.

---

## Правило 1: Сначала READ, потом ACT

**ВСЕГДА** перед любыми операциями с файлами:

1. **Прочитать** все упомянутые файлы целиком
2. **Проверить** текущую структуру директорий (`ls -la`)
3. **Понять** что где находится и зачем
4. **Спросить** у Мансура, если неясно
5. **Только потом** действовать

**Запрещено:**
- Угадывать содержимое файлов по названию
- Создавать файлы "на всякий случай"
- Перемещать/удалять без чтения
- Предполагать структуру без проверки

---

## Правило 2: Структура work/ священна

```
work/
├── specs/          ← Технические задания ОТ МАНСУРА
│   └── TZ_N.md     ← Что нужно сделать (задание)
├── reports/        ← Отчёты ОТ CLAUDE
│   └── TZ_N_report.md  ← Что сделано (результат)
├── scripts/        ← Скрипты для выполнения TZ
└── data/           ← Выходные данные (CSV, графики)
```

**Мнемоника:**
- **specs** = specification = задание = **от Мансура**
- **reports** = результат = отчёт = **от Claude**

**Если путаешься:**
1. Открой `work/specs/TZ_N.md` — там будет задание в стиле "Claude Code, вот задача..."
2. Открой `work/reports/TZ_N_report.md` — там будет отчёт в стиле "# TZ_N Report: ..."

---

## Правило 3: Чеклист перед изменением файловой структуры

Перед любым `mv`, `rm`, `cp`, `Write` в `work/` или `memory/`:

- [ ] Прочитал все упомянутые файлы?
- [ ] Проверил `ls -la` в целевой директории?
- [ ] Понял, что где находится и зачем?
- [ ] Уверен, что не создаю дубли?
- [ ] Уверен, что не удаляю нужное?
- [ ] Если неуверен — спросил у Мансура?

**Только после всех галочек** — действовать.

---

## Правило 4: После изменений — обновить индексы

После **любого** изменения файловой структуры:

1. Обновить `memory/TZ_STATUS.md` (если касается TZ)
2. Обновить `memory/MEMORY_INDEX.md` (если касается памяти)
3. Проверить консистентность всех ссылок

**Как проверить консистентность:**
```bash
# Все файлы в memory/ существуют?
ls -1 /Volumes/MansurSSD/MAS_datasets_research/memory/

# Все TZ в work/ на месте?
ls -1 /Volumes/MansurSSD/MAS_datasets_research/work/specs/
ls -1 /Volumes/MansurSSD/MAS_datasets_research/work/reports/

# Нет ли битых ссылок в MEMORY_INDEX.md?
grep -o '\[.*\](.*\.md)' memory/MEMORY_INDEX.md
```

---

## Правило 5: Не угадывать — спрашивать

Если **хоть что-то** неясно:
- Где должен быть файл?
- Что в нём должно быть?
- Как называется?
- Нужно ли его создавать/удалять?

**→ СПРОСИТЬ У МАНСУРА**

Лучше задать "глупый" вопрос, чем создать хаос в файловой структуре.

---

## Как применять

**Перед началом работы с TZ:**
1. Прочитать этот файл
2. Прочитать `memory/TZ_STATUS.md`
3. Проверить `ls work/specs/` и `ls work/reports/`
4. Убедиться, что понимаю текущее состояние

**При любом упоминании файлов:**
1. Сначала READ
2. Потом ACT
3. Потом UPDATE индексы

**При малейшем сомнении:**
→ Спросить у Мансура
