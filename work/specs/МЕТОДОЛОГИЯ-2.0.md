## СЕКЦИЯ I. МОТИВАЦИЯ И КОНТЕКСТ

### 1.1. Проблема: почему BIC из библиотеки `reliability` недостаточен

Библиотека `reliability` (функция `Fit_Everything`) выбирает «наилучшее» распределение на основе **информационных критериев** — BIC, AICc, AIC. BIC определяется как $-2\ln L + k\ln n$.

**Почему это относительная мера:** BIC штрафует за избыточную сложность (параметры $k$) и за объём данных ($n$). Но он **не имеет критической области**. По нему нельзя сказать «модель верна» — можно лишь сказать «модель А предпочтительнее модели Б среди кандидатов».

**Почему это опасно:** Если все 12 кандидтов описывают физический процесс плохо, `Fit_Everything` всё равно выберет «лучшего» из худших. Симулятор получит распределение, которое визуально приемлемо на графике, но выдаёт отрицательные вероятности в хвостах или систематически занижает риск.

**Пример из практики:** Пользователь подаёт 847 траекторий агентов LLM. `Fit_Everything` говорит: «Weibull_2P с $\alpha=4200$, $\beta=1.3$ — лучший BIC». BIC = 5234. Второй кандидат — Lognormal — BIC = 5241. Разница 7 единиц. Пользователь принимает Weibull. Но p-value теста согласия = 0.003. Распределение **не подходит**, а BIC этого не показал.

**Отсюда вытекают три требования к алгоритму:**

| Требование | Что оно означает | Что было бы без него |
|---|---|---|
| **Абсолютная оценка** | Алгоритм должен ответить «да» или «нет», а не «лучше/хуже» | Невозможно отсеять все неподходящие распределения |
| **Контроль ошибки I рода** | Вероятность ложно отвергнуть верное распределение ≤ α | Можно случайно отвергнуть хорошую модель |
| **Устойчивость к масштабу данных** | Алгоритм работает на $N=20$ и $N=10^6$ без артефактов | При больших $N$ все тесты отвергают любую модель |

### 1.2. Что делает эту задачу сложной

**Три математических тупика**, которые делают задачу нетривиальной:

**Тупик 1 — Ошибка I рода при переоценке параметров.** Если вы оцениваете параметры распределения $\hat\theta$ по той же выборке $\mathbf{X}$, а потом проверяете согласие $\mathbf{X}$ с $F_0(\hat\theta)$ — это **сложная гипотеза** (параметр известен частично). Теоретическая кривая $F_0(x, \hat\theta)$ уже «прижата» к эмпирическим точкам. Стандартный критерий Колмогорова становится **консервативным**: p-value завышается, ложные модели принимаются.

**Тупик 2 — Парадокс больших выборок.** При $N \to \infty$ мощность любого состоятельного критерия $\to 1$. Это означает: при $N=100\,000$ критерий согласия обнаружит микроскопический шум, который невозможно увидеть глазу. $p$-value $\to 0$. Критерий отвергнет **любое** распределение — в том числе идеально подходящее.

**Тупик 3 — Сингулярность MLE для 3P-распределений.** При оценивании параметров трёхпараметрических распределений (Weibull_3P, Lognormal_3P, Gamma_3P, Loglogistic_3P) функция логарифмического правдоподобия ведёт себя нерегулярно. При $\beta \le 1$ и $\gamma \to x_{(1)}$ она стремится к $+\infty$, что приводит к сбою стандартных численных методов.

### 1.3. Как эти тупики решены в Методологии 2.0

| Тупик | Решение | Где в документе |
|---|---|---|
| 1 — Переоценка параметров | Параметрический бутстреп (численное распределение $D_b^*$) | Секция V, Ветвь A |
| 2 — Парадокс больших выборок | TOST: отказ от p-value, переход к Effect Size с Bootstrap CI | Секция V, Ветвь C |
| 3 — Сингулярность MLE 3P | Сеточная инициализация + блокировка γ при β≤1 + LRT для выбора 2P vs 3P | Секция V, Profile MLE |

## СЕКЦИЯ II. МАТЕМАТИЧЕСКИЙ ФУНДАМЕНТ

### 2.1. Эмпирическая функция распределения (ECDF)

**Определение** (Буре, Парилина, 2018, §1.1.2): Эмпирическая функция распределения $F_n(x)$ — ступенчатая функция:

$$F_n(x) = \frac{1}{n}\sum_{i=1}^n \mathbb{I}(x_i \le x)$$

Скачок в каждой точке $x_{(i)}$ равен $1/n$.

**Практическая формула для KS** (Буре, Парилина, 2018, (2.2.2)):

$$D_n^* = \max\!\left(\max_{1\le i\le n}\left|\frac{i}{n} - F_0(x_{(i)})\right|,\;\max_{1\le i\le n}\left|F_0(x_{(i)}) - \frac{i-1}{n}\right|\right)$$

**Почему именно эта формула:** Она вычисляет максимальный вертикальный разрыв между ступенчатой ECDF и гладкой теоретической CDF в двух точках каждого скачка: на верхней границе ($i/n$) и на нижней границе ($(i-1)/n$). Это гарантирует, что никакое отклонение не будет пропущено.

### 2.2. Предельное распределение статистики Колмогорова

**Формула** (Буре, Парилина, 2018, (2.2.3)):

$$K(x) = 1 + 2\sum_{m=1}^{\infty}(-1)^m e^{-2m^2 x^2}$$

**Для вычисления в коде:** Достаточно суммировать до $m \approx \max(3, \lceil 1/\sqrt{x}\rceil)$ для точности $10^{-6}$.

**Область применимости:** Только для **простой гипотезы** (параметры $F_0$ заданы априори, не оценивались по выборке). Для сложной гипотезы — не применима напрямую.

### 2.3. Критерий ω² (Крамэр — фон Мизес)

**Статистика** (Буре, Парилина, 2018, (2.2.4)):

$$\omega_n^2 = \int_{-\infty}^{\infty}[F_n(x) - F_0(x)]^2\,dF_0(x)$$

**Практическая формула** (Буре, Парилина, 2018, (2.2.5)):

$$\omega_n^2 = \frac{1}{12n} + \sum_{i=1}^{n}\left(F_0(x_i) - \frac{2i-1}{2n}\right)^2$$

**Ключевое отличие от KS:** Взвешивает отклонения по **всему носителю** распределения, а не только в точке максимума. Для моделирования редких событий (хвосты) это может быть критично, но для нашего контекста KS достаточно.

### 2.4. Сложные гипотезы: почему стандартные формулы не работают

**Определение** (Буре, Парилина, 2018, §2.1): Гипотеза $H_0: F_\xi(x) = F_0(x, \theta)$ называется *сложной*, если параметр $\theta$ задан не однозначно, а оценивается по той же выборке.

**Ключевая цитата** (Буре, Парилина, 2018, §2.2.4, с. 38–39):

> *«Статистика $D_n^*$ распределена иначе, чем $D_n$, а статистика $\hat\omega_n^2$ — иначе, чем $\omega_n^2$. Причина: из-за подбора параметра $\theta$ по выборке функции $F_n(x)$ и $F_0(x, \hat\theta)$ оказываются «ближе» друг к другу, чем $F_n(x)$ и $F_0(x)$.»*

> *«Для их применения необходимы новые таблицы распределений... для **каждого** параметрического семейства нужны свои таблицы. **Большинство из них рассчитаны методом Монте-Карло**.»*

**Это прямое академическое обоснование параметрического бутстрепа.** Учебник сам рекомендует Монте-Карло для построения квантилей модифицированных статистик.

### 2.5. Модифицированные статистики: что покрыто таблицами

Учебник (Табл. 2.1, 2.2) предоставляет квантили модифицированных статистик только для **двух** распределений:

**Для нормальности:**

| $\alpha$ | 0.15 | 0.10 | 0.05 | 0.025 | 0.01 |
|---|---|---|---|---|---|
| $D_n^*\left(\sqrt{n} - 0.01 + \frac{0.85}{\sqrt{n}}\right)$ | 0.775 | 0.819 | 0.895 | 0.955 | 1.035 |
| $\hat\omega_n^2\left(1 + \frac{0.5}{n}\right)$ | 0.091 | 0.104 | 0.126 | 0.148 | 0.178 |

**Для экспоненциального:**

| $\alpha$ | 0.15 | 0.10 | 0.05 | 0.025 | 0.01 |
|---|---|---|---|---|---|
| $\left(D_n^* - \frac{0.2}{\sqrt{n}}\right)\left(\sqrt{n} + 0.26 + \frac{0.5}{\sqrt{n}}\right)$ | 0.926 | 0.990 | 1.094 | 1.190 | 1.308 |

### 2.6. LRT для сравнения вложенных моделей

**Формула** (Буре, Парилина, 2018, (3.2.25)):

$$LR = 2(\ln L_1 - \ln L_0) \;\xrightarrow{d}\; \chi^2_q$$

где $q$ — число дополнительных параметров.

**Условие применимости:** Обе модели должны быть правильно специфицированы. Применение для 2P ⊂ 3P (вложенные модели, $q=1$): если $p_{\text{LRT}} > 0.05$ — дополнительный параметр $\gamma$ статистически незначим, используем 2P.

## СЕКЦИЯ III. ФИЛОСОФИЯ: ПОЧЕМУ ИМЕННО ТАК

### 3.1. Архитектура «две функции» вместо одной

**Альтернатива A: Одна функция «black box».** На вход — данные и тип распределения, на выход — вердикт. Всё внутреннее скрыто.

**Почему отвергнута:** При сбое или неожиданном вердикте пользователь не может понять причину. Кроме того, сплит-валидация (50/50) требует, чтобы одну часть данных обрабатывала функция фитинга, а другую — функция тестирования. Это two-stage процесс, который невозможно свернуть в одну функцию без нарушения информационной изоляции.

**Альтернатива B: Три функции (селектор → фиттер → валидатор).**

**Почему отвергнута:** Усложняет интерфейс. Между функциями появляются промежуточные данные, которые нужно передавать (калибровочная выборка, вектор параметров, N_max). Две функции — минимальное число, при котором достигается полное разделение стратегии и вычислений.

**Решение: Две функции.** Function 1 — стратегический селектор. Function 2 — универсальное вычислительное ядро. Оператор выполняет сплит между ними.

### 3.2. Почему Profile MLE для 3P, а не просто MLE

**Альтернатива: Фиксировать γ пользователем.**

**Проблема:** Пользователь не знает истинное значение гарантированного порога $\gamma$. Если зафиксировать $\gamma$ неверно — результат будет неправильным независимо от качества данных.

**Альтернатива: Параметрический поиск γ совместно с α, β.**

**Проблема:** Функция правдоподобия $\ln L(\alpha, \beta, \gamma)$ при $\gamma \to x_{(1)}$ и $\beta \le 1$ неограниченно возрастает. Стандартные градиентные методы (Ньютон-Рафсон, BFGS) не работают — они «проваливаются» в сингулярность.

**Решение: Profile MLE.** Внешний одномерный поиск по γ, внутренний MLE для α и β. Это два уровня оптимизации, разделённые для устойчивости. Дополнительно: экспресс-проверка β≤1 с блокировкой γ≡0 (переход к 2P), LRT для финального выбора 2P vs 3P.

### 3.3. Почему TOST, а не классический p-value, для больших данных

**Альтернатива: Снизить α при больших N.** Например, $\alpha_n = \alpha_0 / \sqrt{n}$.

**Проблема:** Это эвристика. Нет строгого обоснования, почему делить именно на $\sqrt{n}$, а не на $n$ или $\log n$. Рецензент это отклонит.

**Альтернатива: BIC.** BIC включает штраф $\ln n$, что замедляет рост «ложных» параметров.

**Проблема:** BIC — критерий **сравнения моделей**, а не критерия согласия. BIC хорош для выбора лучшего кандидата, но не для ответа на вопрос «подходит ли эта модель». Кроме того, BIC «прощает» плохое качество на хвостах — а для инженерии надёжности хвосты критичны.

**Решение: TOST.** Вместо «модель идеальна» ($p$-value) — «модель практически пригодна» ($D_{\text{real}} \le \epsilon$). Инженерный допуск $\epsilon$ — это бизнес-требование, не статистическое. Результат: «С вероятностью >95% максимальное отклонение CDF от модели не превышает 3%. Модель пригодна для симулятора.»

### 3.4. Почему Jittering, а не просто игнорировать ties

**Альтернатива: Использовать непрерывную поправку для ties.**

**Проблема:** Такие поправки существуют (Hajek, 1969), но они работают только для конкретных типов связок. Для произвольных данных (например, округлённые логи) они неточны.

**Решение: Jittering.** Добавление микроскопического шума $\mathcal{U}(-\delta, +\delta)$ разрывает все связи, восстанавливая непрерывность. При $\delta \to 0$ это приближение сколь угодно точное. Защита области определения (`max(support + δ, x + e)`) предотвращает выход за пределы допустимых значений.

### 3.5. Почему именно K=100 сплитов, а не K=10 или K=∞

**При K=10:** Недостаточная стабилизация. Стандартное отклонение медианы p-value всё ещё велико. Разные запуски могут давать разные вердикты.

**При K=∞ (полный перебор всех разбиений):** Комбинаторно взрывной. Для $N=1000$ число разбиений $\approx 2^{999}$. Невозможно.

**При K=100:** Эмпирически достаточная стабилизация. $K=100$ — стандартное значение в бутстреп-литературе. Медиана 100 p-values — робастная оценка. Квантильная коррекция $2 \cdot \text{median}(p)$ компенсирует систематическое смещение агрегации.

### 3.6. Почему Meinshausen correction именно $2 \cdot \text{median}(p)$

Это **поправка Бонферрони для порядковых статистик.** При $K$ независимых тестах консервативная поправка Бонферрони: $\alpha/K$. Медиана — это $\lceil K/2 \rceil$-я порядковая статистика. При $K=100$ медиана — 50-я. Поправка Бонферрони для 50-й статистики: $2 \cdot \text{median}(p)$. Это математически точное преобразование, доказанное в работе Meinshausen & Bühlmann (2006).

### 4.2. Функция 1: scale_selector

**Назначение:** Определить, какой режим вычислений применим к данным, и рассчитать критические барьеры $N_{\min}$ и $N_{\max}$.

**Входные параметры:**

| Параметр | Смысл | Типичное значение |
|---|---|---|
| $\mathbf{X}$ | Эмпирический ряд | $N$ элементов |
| $\epsilon$ | Инженерный допуск | $0.03$ |
| $\alpha$ | Уровень значимости | $0.05$ |
| $1-\beta_{\text{target}}$ | Целевая мощность | $0.80$ |

**Выход:**

| Значение | Когда |
|---|---|
| `UNDERPOWERED` | $N < N_{\min}/2$ |
| `BOOTSTRAP` | $N_{\min}/2 \le N < N_{\min}$ |
| `SPLIT_EXACT` | $N_{\min} \le N \le N_{\max}$ |
| `BIG_DATA` | $N > N_{\max}$ |

Плюс: $N_{\min}$, $N_{\max}$, $\xi$, рекомендации (при UNDERPOWERED).

### 4.3. Функция 2: validate

**Назначение:** Проверить согласие тестовых данных с теоретическим распределением.

**Входные параметры:**

| Параметр | Смысл |
|---|---|
| `X_test` | Тестовые данные |
| `F_frozen` | Замороженное распределение с фиксированными параметрами |
| `trained_on_same_data` | `True` — параметры оценены по X_test; `False` — независимые параметры |
| `N_max` | Верхний барьер (из Function 1) |
| `event_mask` | `None` или массив 0/1 (1 = событие, 0 = цензурирование) |
| `epsilon` | Инженерный допуск |

### 5.2. Адаптивный расчёт ξ

$$\xi = \max\!\left(\frac{\min_{1\le i<N}(x_{i+1}-x_i)}{100},\;\Delta_{\text{float}},\;10^{-10}\right)$$

**Зачем:** Параметр $\xi$ — это оценка неустранимого системного шума. Мы не можем «угадать» его априорно, поэтому вычисляем из данных: минимальный шаг дискретизации делим на 100. Если данные идеально непрерывны (минимальный шаг ≈ machine epsilon) — используем машинное эпсилон. Потолок $10^{-10}$ гарантирует ненулевое значение.

**Физический смысл:** Если логи записываются с точностью до целых символов, минимальный шаг = 1. Делим на 100 → ξ = 0.01. Если логи в микросекундах — шаг = 10⁻⁶ → ξ = 10⁻⁸.

### 5.3. Расчёт N_max (верхний барьер)

$$N_{\max} = 2\cdot\left\lceil\left(\frac{K_{1-\alpha}}{\xi}\right)^2\right\rceil$$

где $K_{q}$ — квантиль предельного распределения Колмогорова.

**Пример:** $\alpha=0.05$, $\xi=0.005$ → $K_{0.95}=1.358$ → $N_{\max}=295\,300$.

**Зачем:** При $N > N_{\max}$ мощность теста против шума $\xi$ гарантированно → 1. Это означает: $p$-value гарантированно $\to 0$ даже на абсолютно верном распределении. Переход в режим TOST — единственный математически корректный выход.

### 5.4. Расчёт N_min (нижний барьер) — численный метод

Асимптотическая формула $N_{\min}\approx 2\cdot(K_{1-\alpha}+K_{1-\beta})^2/\epsilon^2$ неточна при $N<3000$. Вместо неё — численный Monte-Carlo:

```
для N_test от 50 до 3000 с шагом 50:
    для trial = 1..1000:
        X_null ~ F_0(θ̂)              # нулевое распределение
        D = KS_stat(X_null)
        p = 1 - K(D · sqrt(N_test))
        power = fraction(отвержений на альтернативе)
    avg_power[N_test] = mean(power_trials)
N_test_min = min{N_test : avg_power[N_test] ≥ 1-β}
N_min = 2 × N_test_min
```

Результат кэшируется в `~/.cache/distfit_validator/n_barriers_cache.json` с хэш-ключом из тройки $(\epsilon, \alpha, 1-\beta)$.

**Fallback:** При $N > 3000$ — асимптотическая формула. При $N < 50$ — код `UNDERPOWERED`.

### 5.5. UNDERPOWERED — 4 сценария

При $N < N_{\min}/2$ возврат включает рекомендации:

| Код | Условие | Рекомендация |
|---|---|---|
| `pilot_study` | Сбор данных можно продолжить | Оценить $N_{\text{target}}$ для мощности 80%; отложить анализ |
| `bayesian_regularization` | Данные ценны и редки | Слабоинформативные priors; результат = exploratory |
| `equivalence_to_None` | Информацию нельзя получить | Описательная статистика; модель не выбирать |
| `defer_to_meta_analysis` | Данные можно опубликовать | Депонировать для будущего мета-анализа |

### 5.6. Jittering — единая точка входа

```python
def _safe_jitter(x, support_lower, delta):
    jittered = x + uniform(-delta, +delta)
    return max(support_lower + delta, jittered)
```

| Распределение | `support_lower` |
|---|---|
| Normal, Gumbel | $-\infty$ (без ограничений) |
| 2P с $x\ge 0$ | $0$ |
| 3P | $\hat\gamma$ |
| Lognormal (2P/3P) | $\hat\gamma$ или $10^{-10}$ при $\hat\gamma=0$ |

$\delta = \max(10^{-4}\cdot\bar{x},\;1e-10)$. Ключевое: jittering применяется **один раз** в начале Function 2, до любого фитинга или расчёта ECDF. Параметры, ECDF и бутстреп работают с одним и тем же джиттеренным массивом.

### 5.7. Profile MLE для 3P-распределений (шаг 1.4.3.1)

**5.7.1. Subtask A: Предварительная проверка β**

Линейная регрессия на вейбулловской (или аналоговой) бумаге. Если $\beta_{\text{prelim}} \le 1$ → автоматический переход к 2P с кодом `γ_LOCKED_BY_SINGULARITY`.

**Зачем:** При $\beta \le 1$ функция правдоподобия уходит в $+\infty$ при $\gamma \to x_{(1)}$. Предотвращаем сбой численных методов.

**5.7.2. Subtask B: Grid Search (100 узлов)**

$\gamma$-сетка: $100$ точек от $0$ до $x_{(1)} - 10^{-6}$. В каждой точке — внутренний 2P MLE, вычисление $\ln L$. Если $\Delta_{\text{LL}} > 1.0$ (разница между лучшим и третьим лучшим) → fine grid из 201 точки вокруг доминирующего пика.

**Зачем:** Профильное правдоподобие $\ln L(\gamma)$ может иметь несколько локальных максимумов. Grid search гарантирует нахождение области глобального максимума.

**5.7.3. Subtask C: Brent 1D Optimization**

Метод Брента: комбинация дихотомии, секущей и обратной параболы. tol_abs=$10^{-6}$, tol_rel=$10^{-8}$, max_iter=200. Fallback: если не сошёлся — используется grid-оценка с пометкой `CONVERGENCE_WARNING`.

**5.7.4. Subtask D: Internal 2P MLE (L-BFGS-B)**

Контекст определяет точность:

| Контекст | gtol | max_iter | Назначение |
|---|---|---|---|
| `for_grid` | $10^{-6}$ | 50 | Быстрый approximate на 100 точках сетки |
| `for_brent` | $10^{-8}$ | 100 | Standard — внутри Brent |
| `final` | $10^{-9}$ | 200 | Финальная оценка |

**5.7.5. Subtask E: LRT 2P vs 3P**

$$\lambda = 2(\ln L_{3P} - \ln L_{2P}),\qquad p_{\text{LRT}} = 1 - \chi^2(\lambda, df=1)$$

**Решающее правило:**

| $p_{\text{LRT}}$ | Результат | Код |
|---|---|---|
| $> 0.10$ | 2P | `γ_NOT_SIGNIFICANT` |
| $0.05 < \le 0.10$ | 3P | `γ_MARGINAL` |
| $\le 0.05$ | 3P | (нет кода) |
| + `γ_NEAR_BOUNDARY` | + `γ_NEAR_BOUNDARY` | |
| + `γ_NEAR_BOUNDARY AND p<0.10` | + `DOUBLE_WARNING` | |

### 5.8. Ветвь A: Complex Hypothesis (trained_on_same_data=True)

**Ключевое отличие от Ветви B/C:** Параметры оценены по тем же данным → сложная гипотеза. Стандартные таблицы неприменимы. Единственный математически строгий путь — параметрический бутстреп.

**Алгоритм:**

1. Jittering X_test → X_j
2. Profile MLE / MLE → θ_final, γ_final
3. $D_{\text{obs}}$ = sup |ECDF(X_j) - F_0(X_j, θ_final)|
4. $B=10\,000$ итераций параметрического бутстрепа:
   - Генерация $X^* \sim F_0(\theta_{\text{final}}, \gamma_{\text{final}})$ (метод обратной трансформации)
   - Jittering $X^*$
   - Быстрый MLE на $X^*$ (γ фиксирован — экономия 99%)
   - $D_b^* = \text{sup}|\text{ECDF}(X^*_b) - F_0(X^*_b, \hat\theta_b)|$
5. $p$-value = $\frac{1}{B}\sum \mathbb{I}(D_b^* \ge D_{\text{obs}})$
6. Skewness check: если $|skew| > 0.5$ → предупреждение в выводе
7. Вердикт: ACCEPT если $p \ge \alpha$, REJECT если $p < \alpha$

### 5.9. Ветвь B: Simple Hypothesis (trained_on_same_data=False, N_test ≤ N_max/2)

**Ключевое отличие:** Параметры независимы от тестовой выборки → простая гипотеза. Стандартное распределение $K(x)$ применимо.

**Алгоритм:**

1. $K=100$ независимых сплитов (50/50)
2. На каждом сплите: $D_k$ = sup |ECDF(X_test^k) - F_0(X_test^k, θ̂_fit^k)|
3. $\tilde{D} = \text{median}(D_1,\dots,D_K)$
4. Для каждого $D_k$: $p_k = 1 - K(D_k \cdot \sqrt{N_{\text{test}}/2})$
5. $p_{\text{final}} = \min(1,\; 2 \cdot \text{median}(p_1,\dots,p_K))$
6. Вердикт: ACCEPT / REJECT

**Почему 2·median(p):** Meinshausen correction. При агрегации K=100 p-values медиана теряет свойство равномерности на [0,1]. Умножение на 2 — поправка Бонферрони, восстанавливающая контроль над ошибкой I рода.

### 5.10. Ветвь C: Bootstrap CI Equivalence (Big Data OR Censored Data)

**Ключевое отличие:** Классический $p$-value неприменим: либо избыточная мощность (Big Data), либо структура цензурирования (Censored Data).

**Алгоритм:**

1. **Типизация:**
   - censored = (event_mask ≠ None AND есть нули в event_mask)
   - Если censored: bootstrap_strategy = "parametric"
   - Если big_data: bootstrap_strategy = "resampling" или "parametric"

2. **D_real:**
   - Censored: sup_distance_KM (Каплана-Мейера)
   - Big data: стандартный sup |ECDF - F_0|

3. **Bootstrap CI (B=5000):**
   - При censored: генерация из $F_0(\hat\theta)$ + сохранение event_mask на каждой итерации
   - При big_data (resampling): простой ресэмплинг из X_test
   - $D_{\text{low}} = Q_{2.5}(D_{\text{boot}})$, $D_{\text{up}} = Q_{97.5}(D_{\text{boot}})$

4. **Вердикт:** ACCEPT_EQUIVALENCE если $D_{\text{up}} \le \epsilon$, иначе REJECT_EQUIVALENCE

5. **Рекомендации:**

| Margin | Рекомендация |
|---|---|
| $> 0$ | ACCEPT |
| $(-0.01, 0]$ | «Незначительное превышение; рассмотреть ε=...» |
| $(-0.05, -0.01]$ | «Отклонение существенно. 3P-версия?» |
| $\le -0.05$ | «Структурное несоответствие. Мультимодальность?» |

### 5.11. Обработка цензурированных данных (Kaplan-Meier ECDF)

Если `event_mask` содержит цензурированные наблюдения:

$$\hat{S}(t) = \prod_{t_i \le t}\left(1 - \frac{d_i}{n_i}\right), \qquad F_n(t) = 1 - \hat{S}(t)$$

**Sup distance для KM-ECDF** (уникальная для цензурированных данных):

$D = \max$ по трём типам точек:
1. $t_i$ (точки событий): $|F_n(t_i) - F_0(t_i)|$
2. $t_i^-$ (левая граница ступеньки): $|F_n(t_i) - d_i/n_i - F_0(t_i)|$
3. $\tau$ (последняя точка горизонта): $|F_n(\tau) - F_0(\tau)|$

**Важно:** Censored data → Branch C (TOST). Branch A и B **не поддерживают** цензурированные данные. Это консервативное ограничение: параметрический бутстреп для цензурированных данных требует сохранения структуры цензурирования (event_mask) на каждой итерации — и TOST с параметрическим бутстрепом это обеспечивает.

## СЕКЦИЯ VI. ДЕВЯТЬ ЗАЩИТНЫХ МЕХАНИЗМОВ

Каждый механизм — это уязвимость, обнаруженная при верификации, и её решение.

### Механизм 1: Jittering с защитой области определения

**Уязвимость:** Jittering может вывести данные за пределы области определения (отрицательные значения для LN, W, G).

**Решение:** `max(support_lower + δ, x + uniform(-δ, +δ))`.

### Механизм 2: N_max в интерфейсе Function 2

**Уязвимость:** Без N_max невозможно определить, какая ветвь (B или C) применима.

**Решение:** N_max передаётся из Function 1 как явный параметр.

### Механизм 3: Censored data — жёсткий фильтр

**Уязвимость:** Branch A/B не могут корректно обрабатывать цензурированные данные.

**Решение:** Censored data → Branch C. Внутри Branch C — параметрический бутстреп с сохранением event_mask.

### Механизм 4: UNDERPOWERED — рекомендации

**Уязвимость:** При $N < N_{\min}/2$ конвейер просто останавливается без объяснения.

**Решение:** 4 сценария: pilot_study, bayesian_regularization, equivalence_to_None, defer_to_meta_analysis.

### Механизм 5: Асимптотическая формула N_min неточна

**Уязвимость:** $N_{\min}\approx 2\cdot(K_{1-\alpha}+K_{1-\beta})^2/\epsilon^2$ занижает порог при $N<3000$.

**Решение:** Численный Monte-Carlo расчёт для диапазона $N_{\text{test}} \in [50,3000]$. Кэширование результата.

### Механизм 6: TOST-диагностика при отвержении

**Уязвимость:** REJECT_EQUIVALENCE без диагностики — непрозрачный вывод.

**Решение:** TOSTDiagnostics dataclass: D_real, D_low, D_up, margin, epsilon, verdict, recommendation.

### Механизм 7: Многократный сплит (K=100)

**Уязвимость:** Единичный сплит 50/50 даёт вариативные вердикты на тяжёлых хвостах.

**Решение:** $K=100$ сплитов, медианная агрегация $D_k$, Meinshausen correction $2 \cdot \text{median}(p)$.

### Механизм 8: Profile MLE — сеточная инициализация

**Уязвимость:** Brent может сойтись к локальному максимуму при плохой стартовой точке.

**Решение:** Grid search 100 узлов → fine grid 201 при $\Delta_{\text{LL}} > 1.0$ → Brent из лучшей точки.

### Механизм 9: LRT для 2P vs 3P

**Уязвимость:** Решение «брать 3P или 2P» на основе β≤1 — эвристика.

**Решение:** LRT с $\chi^2_1$: если $p_{\text{LRT}} > 0.05$ — 2P, иначе — 3P. Строгий статистический тест.

## СЕКЦИЯ I. МОТИВАЦИЯ И КОНТЕКСТ

### 1.1. Проблема: почему BIC из библиотеки `reliability` недостаточен

Библиотека `reliability` (функция `Fit_Everything`) выбирает «наилучшее» распределение на основе **информационных критериев** — BIC, AICc, AIC. BIC определяется как $-2\ln L + k\ln n$.

**Почему это относительная мера:** BIC штрафует за избыточную сложность (параметры $k$) и за объём данных ($n$). Но он **не имеет критической области**. По нему нельзя сказать «модель верна» — можно лишь сказать «модель А предпочтительнее модели Б среди кандидатов».

**Почему это опасно:** Если все 12 кандидатов описывают физический процесс плохо, `Fit_Everything` всё равно выберет «лучшего» из худших. Симулятор получит распределение, которое визуально приемлемо на графике, но выдаёт систематически заниженный риск в хвостах.

**Пример:** Пользователь подаёт 847 траекторий. `Fit_Everything` говорит: «Weibull_2P с $\alpha=4200$, $\beta=1.3$ — лучший BIC». Второй кандидат — Lognormal — BIC = 5241. Разница 7 единиц. Пользователь принимает Weibull. Но $p$-value теста согласия = 0.003. Распределение **не подходит**, а BIC этого не показал.

**Три требования к алгоритму:**

| Требование | Что оно означает |
|---|---|
| **Абсолютная оценка** | Ответ «да» или «нет», а не «лучше/хуже» |
| **Контроль ошибки I рода** | Вероятность ложно отвергнуть верное распределение $\le \alpha$ |
| **Устойчивость к масштабу данных** | Работает на $N=20$ и $N=10^6$ без артефактов |

### 1.2. Три математических тупика

**Тупик 1 — Ошибка I рода при переоценке параметров.** Если параметры $\hat\theta$ оценены по той же выборке $\mathbf{X}$, а затем проверяется согласие $\mathbf{X}$ с $F_0(\hat\theta)$ — это **сложная гипотеза**. Теоретическая кривая уже «прижата» к эмпирическим точкам. Стандартный критерий Колмогорова становится консервативным: $p$-value завышается.

**Тупик 2 — Парадокс больших выборок.** При $N \to \infty$ мощность любого состоятельного критерия $\to 1$. При $N=100\,000$ критерий обнаружит микроскопический шум. $p$-value $\to 0$. Критерий отвергнет **любое** распределение — в том числе идеально подходящее.

**Тупик 3 — Сингулярность MLE для 3P-распределений.** При $\beta \le 1$ и $\gamma \to x_{(1)}$ функция логарифмического правдоподобия стремится к $+\infty$, что приводит к сбою стандартных численных методов.

### 1.3. Решения

| Тупик | Решение | Где в документе |
|---|---|---|
| 1 — Переоценка параметров | Параметрический бутстреп | Секция V, 5.8 |
| 2 — Парадокс больших выборок | TOST: Effect Size + Bootstrap CI | Секция V, 5.10 |
| 3 — Сингулярность MLE 3P | Сеточная инициализация + блокировка γ + LRT | Секция V, 5.7 |

## СЕКЦИЯ II. МАТЕМАТИЧЕСКИЙ ФУНДАМЕНТ

### 2.1. Эмпирическая функция распределения (ECDF)

**Определение** (Буре, Парилина, 2018, §1.1.2):

$$F_n(x) = \frac{1}{n}\sum_{i=1}^n \mathbb{I}(x_i \le x)$$

Скачок в каждой точке $x_{(i)}$ равен $1/n$.

**Практическая формула KS** (Буре, Парилина, 2018, (2.2.2)):

$$D_n^* = \max\!\left(\max_{1\le i\le n}\left|\frac{i}{n} - F_0(x_{(i)})\right|,\;\max_{1\le i\le n}\left|F_0(x_{(i)}) - \frac{i-1}{n}\right|\right)$$

### 2.2. Предельное распределение статистики Колмогорова

**Формула** (Буре, Парилина, 2018, (2.2.3)):

$$K(x) = 1 + 2\sum_{m=1}^{\infty}(-1)^m e^{-2m^2 x^2}$$

При вычислении в коде достаточно суммировать до $m \approx \max(3,\;\lceil 1/\sqrt{x}\rceil)$ для точности $10^{-6}$.

**Область применимости:** Только для **простой гипотезы** (параметры заданы априори). Для сложной — не применима напрямую.

### 2.3. Критерий ω² (Крамэр — фон Мизес)

**Практическая формула** (Буре, Парилина, 2018, (2.2.5)):

$$\omega_n^2 = \frac{1}{12n} + \sum_{i=1}^{n}\left(F_0(x_i) - \frac{2i-1}{2n}\right)^2$$

Взвешивает отклонения по **всему носителю**, а не только в точке максимума.

### 2.4. Сложные гипотезы: почему стандартные формулы не работают

**Ключевая цитата** (Буре, Парилина, 2018, §2.2.4, с. 38–39):

> *«Статистика $D_n^*$ распределена иначе, чем $D_n$, а статистика $\hat\omega_n^2$ — иначе, чем $\omega_n^2$. Причина: из-за подбора параметра $\theta$ по выборке функции $F_n(x)$ и $F_0(x, \hat\theta)$ оказываются «ближе» друг к другу.»*

> *«Для их применения необходимы новые таблицы распределений... для **каждого** параметрического семейства нужны свои таблицы. **Большинство из них рассчитаны методом Монте-Карло**.»*

Это — прямое академическое обоснование параметрического бутстрепа.

### 2.5. Модифицированные статистики: что покрыто таблицами

Учебник (Табл. 2.1, 2.2) покрывает **только нормальное и экспоненциальное**. Для 10 из 12 распределений алгоритма таблиц **нет**. Единственный метод — параметрический бутстреп.

### 2.6. LRT для сравнения вложенных моделей

**Формула** (Буре, Парилина, 2018, (3.2.25)):

$$LR = 2(\ln L_1 - \ln L_0) \;\xrightarrow{d}\; \chi^2_q$$

Для 2P ⊂ 3P: $q=1$.

## СЕКЦИЯ III. ФИЛОСОФИЯ РЕШЕНИЙ

### 3.1. Архитектура «две функции»

**Две функции — минимальное число**, при котором достигается полное разделение стратегии и вычислений. Сплит-валидация требует, чтобы одну часть данных обрабатывала функция фитинга, а другую — функция тестирования.

### 3.2. Почему Profile MLE для 3P, а не просто MLE

Экспресс-проверка $\beta \le 1$ с блокировкой γ≡0 предотвращает сбой. LRT для финального выбора 2P vs 3P — строгий статистический тест, а не эвристика.

### 3.3. Почему TOST для больших данных

Вместо «модель идеальна» ($p$-value) — «модель практически пригодна» ($D_{\text{real}} \le \epsilon$). Инженерный допуск $\epsilon$ — это бизнес-требование, не статистическое.

### 3.4. Почему K=100 сплитов

$K=100$ — стандартное значение в бутстреп-литературе. Медиана 100 $p$-values — робастная оценка. Квантильная коррекция $2 \cdot \text{median}(p)$ компенсирует систематическое смещение.

### 3.5. Почему Meinshausen correction именно $2 \cdot \text{median}(p)$

При $K$ независимых тестах медиана — это $\lceil K/2 \rceil$-я порядковая статистика. Поправка Бонферрони для медианы: $2 \cdot \text{median}(p)$. Доказательство: Meinshausen & Bühlmann (2006), JASA, 101(476), 1361–1372.

### 5.2. Адаптивный расчёт ξ

$$\xi = \max\!\left(\frac{\min_{1\le i<N}(x_{i+1}-x_i)}{100},\;\Delta_{\text{float}},\;10^{-10}\right)$$

Оценка неустранимого системного шума из данных: минимальный шаг дискретизации делится на 100. Потолок $10^{-10}$ гарантирует ненулевое значение.

### 5.3. Расчёт N_max

$$N_{\max} = 2\cdot\left\lceil\left(\frac{K_{1-\alpha}}{\xi}\right)^2\right\rceil$$

где $K_q$ — квантиль предельного распределения Колмогорова. При $\alpha=0.05$, $K_{0.95}=1.358$.

Пример: $\xi=0.005$ → $N_{\max}=295\,300$.

### 5.4. Расчёт N_min — численный метод

Асимптотическая формула неточна при $N<3000$. Вместо неё — численный Monte-Carlo:

```
для N_test от 50 до 3000 с шагом 50:
    для trial = 1..1000:
        X_null ~ F_0(θ̂)
        D = KS_stat(X_null)
        power = fraction(отвержений на альтернативе с отклонением ε)
    avg_power[N_test] = mean(power_trials)
N_test_min = min{N_test : avg_power[N_test] ≥ 1-β}
N_min = 2 × N_test_min
```

**Кэширование:** Результат сохраняется в `~/.cache/distfit_validator/n_barriers_cache.json` с хэш-ключом из тройки $(\epsilon, \alpha, 1-\beta)$. При повторном вызове с теми же параметрами — мгновенный возврат.

**Fallback при $N > 3000$:** Асимптотическая формула $N_{\min} \approx 2\cdot(K_{1-\alpha}+K_{1-\beta})^2/\epsilon^2$.

**При $N < 50$:** Код `UNDERPOWERED`. Значение $N_{\min}$ не вычисляется. Возвращается код рекомендации `pilot_study` с указанием минимального объёма $N_{\text{target}} = N_{\min}$ для достижения целевой мощности. Это обусловлено тем, что при $N<50$ бутстреп-распределение $D_b^*$ слишком шумное для надёжного вывода.

**[FIX 1] Буферная зона неопределённости.** В интервале $N \in [0.8 \cdot N_{\min},\;1.2 \cdot N_{\min}]$ мощность теста нестабильна — малые изменения $N$ могут приводить к смене режима и скачку $p$-value. В этой зоне Function 1 возвращает **оба** режима (BOOTSTRAP + SPLIT_EXACT). Function 2 вычисляет вердикт по обоим сценариям:
- Если вердикты совпадают → выводится согласованный результат.
- Если вердикты расходятся → выводится **более строгий** вердикт; в вывод добавляется предупреждение:
  `"ZONE_UNCERTAINTY: результат может измениться при незначительном изменении объёма данных. Рекомендуется собрать больше наблюдений."`

### 5.6. Jittering — единая точка входа

```python
def _safe_jitter(x, support_lower, delta):
    jittered = x + uniform(-delta, +delta)
    return max(support_lower + delta, jittered)  # защита области определения
```

| Распределение | `support_lower` |
|---|---|
| Normal, Gumbel | $-\infty$ (без ограничений) |
| 2P с $x\ge 0$ | $0$ |
| 3P | $\hat\gamma$ |
| Lognormal (2P/3P) | $\hat\gamma$ или $10^{-10}$ при $\hat\gamma=0$ |

$\delta = \max(10^{-4}\cdot\bar{x},\;1e-10)$. **Критично:** jittering применяется один раз в начале Function 2, до любого фитинга или расчёта ECDF. Все параметры, ECDF и бутстреп работают с одним джиттеренным массивом.

### 5.8. Ветвь A: Complex Hypothesis (trained_on_same_data=True)

Алгоритм:

1. Jittering X_test → X_j
2. Profile MLE / MLE → θ_final, γ_final
3. $D_{\text{obs}}$ = sup |ECDF(X_j) - F_0(X_j, θ_final)|
4. **[$B=10\,000$ итераций]** параметрический бутстрепа:
   - Генерация $X^* \sim F_0(\theta_{\text{final}}, \gamma_{\text{final}})$ (метод обратной трансформации)
   - Jittering $X^*$
   - Быстрый MLE на $X^*$ (γ фиксирован — экономия 99% вычислений)
   - $D_b^* = \text{sup}|\text{ECDF}(X^*_b) - F_0(X^*_b, \hat\theta_b)|$
5. $p$-value = $\frac{1}{B}\sum \mathbb{I}(D_b^* \ge D_{\text{obs}})$

**[FIX 2] Skewness check:**

$$\text{skew} = \frac{Q_{75} + Q_{25} - 2Q_{50}}{Q_{75} - Q_{25} + 10^{-10}}$$

где $Q_x$ — перцентиль бутстреп-распределения $D_b^*$.

**Выбор порога $|skew| > 0.5$:** При нормальных условиях ($H_0$ верна) бутстреп-распределение $D_b^*$ близко к симметричному, skewness $\approx 0$. При нарушении предпосылок (крайние значения, цензурирование, $\beta \approx 1$) распределение $D_b^*$ становится скошенным. При $|skew| > 0.5$ стандартное $p$-value из ранжировки становится ненадёжным. Рекомендуется симуляционная калибровка: для типичных конфигураций ($N \in \{50, 100, 500\}$, $\beta \in \{0.5, 1.5, 3.0\}$) сгенерировать 1000 выборок из $F_0(\hat\theta)$ и посмотреть распределение skewness $D_b^*$ при истинной $H_0$.

**Если $|skew| > 0.5$:** В вывод добавляется `bootstrap_warning` с текстом: `"Bootstrap distribution skewed (skewness={...}). Consider TOST as alternative."`

**[FIX 5] Параметр B (число бутстреп-итераций):**

| Режим | B | Погрешность $p$-value | Когда |
|---|---|---|---|
| Default | $10\,000$ | $\approx 0.01$ | Стандартная работа |
| Fast | $1\,000$ | $\approx 0.03$ | Интерактивный exploration |
| Ultra | $50\,000$ | $\approx 0.004$ | $N < 100$ — компенсация высокой дисперсии |

Все бутстреп-итерации независимы и могут выполняться параллельно (multiprocessing).

Вердикт: ACCEPT если $p \ge \alpha$, REJECT если $p < \alpha$.

### 5.9. Ветвь B: Simple Hypothesis (trained_on_same_data=False, N_test ≤ N_max/2)

Алгоритм:

1. $K=100$ независимых сплитов (50/50)
2. На каждом сплите: $D_k$ = sup |ECDF(X_test^k) - F_0(X_test^k, θ̂_fit^k)|
3. $\tilde{D} = \text{median}(D_1,\dots,D_K)$
4. Для каждого $D_k$: $p_k = 1 - K(D_k \cdot \sqrt{N_{\text{test}}/2})$
5. $p_{\text{final}} = \min(1,\; 2 \cdot \text{median}(p_1,\dots,p_K))$ — Meinshausen correction
6. Вердикт: ACCEPT / REJECT

### 5.10. Ветвь C: Bootstrap CI Equivalence (Big Data OR Censored Data)

**Типизация:**

- censored = (event_mask ≠ None AND есть нули) → `bootstrap_strategy = "parametric"`
- big_data uncensored → `bootstrap_strategy = "resampling"` (быстрый путь) или "parametric"

**D_real:**

- Censored: sup_distance_KM (Каплана-Мейера)
- Big data: стандартный sup |ECDF - F_0|

**Bootstrap CI (B=5000):**

- При censored: генерация из $F_0(\hat\theta)$ + сохранение event_mask на каждой итерации
- При big_data (resampling): простой ресэмплинг из X_test
- $D_{\text{low}} = Q_{2.5}(D_{\text{boot}})$, $D_{\text{up}} = Q_{97.5}(D_{\text{boot}})$

**Вердикт:** ACCEPT_EQUIVALENCE если $D_{\text{up}} \le \epsilon$, иначе REJECT_EQUIVALENCE.

**Рекомендации:**

| Margin | Рекомендация |
|---|---|
| $> 0$ | ACCEPT |
| $(-0.01, 0]$ | «Незначительное превышение. Рассмотреть ε={ε+|margin|:.4f}» |
| $(-0.05, -0.01]$ | «Отклонение существенно. Рассмотреть 3P-версию распределения» |
| $\le -0.05$ | «Структурное несоответствие. Вероятна мультимодальность. Проверить Weibull_Mixture» |

### 5.11. Обработка цензурированных данных (Kaplan-Meier ECDF)

$$\hat{S}(t) = \prod_{t_i \le t}\left(1 - \frac{d_i}{n_i}\right), \qquad F_n(t) = 1 - \hat{S}(t)$$

**Sup distance для KM-ECDF:**

$D = \max$ по трём типам точек:
1. $t_i$ (точки событий): $|F_n(t_i) - F_0(t_i)|$
2. $t_i^-$ (левая граница ступеньки): $|F_n(t_i) - d_i/n_i - F_0(t_i)|$
3. $\tau$ (последняя точка горизонта): $|F_n(\tau) - F_0(\tau)|$

**Важно:** Censored data → Branch C. Branch A/B не поддерживают цензурированные данные.

**Loglogistic — единственное исключение.** scipy не имеет класса `loglogistic`. Реализуется тремя функциями:

```python
class custom_loglogistic:
    """Реализация логлогистического распределения на scipy.special"""
    def __init__(self, alpha, beta):
        self.alpha = alpha
        self.beta = beta
    def cdf(self, x):
        z = x / self.alpha
        return 1 / (1 + z ** (-self.beta))
    def ppf(self, u):
        # u ∈ (0, 1)
        # x = α · (u^(−1/β) − 1)^(−1)
        return self.alpha * ((u ** (-1.0 / self.beta)) - 1) ** (-1.0 / self.beta)
    def rvs(self, size=None):
        u = np.random.uniform(size=size)
        return self.ppf(u)
```

Аналогично для `custom_loglogistic_3p` с добавлением сдвига `γ`: в PPF: `γ + self.ppf(u)`.

### 8.4. Что реализуется вручную и почему

Для каждого компонента указывается: источник математической документации (для реализации), причина отказа от готовой библиотеки, риск и стратегия верификации.

#### 8.4.1. Параметрический бутстрап для цензурированных данных (Fleming's modification)

**Источник:** [Исследование библиотек, Блок 4] — реализация GofCens (GPL), статья Fleming et al. (1980). Математическая формула модифицированной статистики:

$$D_n^* = \sup_t \frac{|\hat{F}_n(t) - F_0(t, \hat{\theta})|}{\hat{\sigma}(t)}$$

где $\hat{\sigma}(t)$ — оценка дисперсии Гринвуда:

$$\hat{\sigma}^2(t) = \hat{F}_n(t)^2 \sum_{t_i \le t}\frac{d_i}{n_i(n_i - d_i)}$$

**Почему вручную:** `scipy.stats.goodness_of_fit` не поддерживает `CensoredData` в качестве входных данных. Эта функция работает только с полными (uncensored) массивами. Для цензурированных данных параметрический бутстрап реализуется самостоятельно.

**Причина отказа от GofCens:** GofCens распространяется под GPL-3. Использование через rpy2 создаёт derivative work — лицензионное нарушение.

**Реализация:** scipy.stats.CensoredData + .ecdf() предоставляет Kaplan-Meier ECDF. На каждой бутстреп-итерации:
1. Симуляция $X^* \sim F_0(\hat\theta)$ (NumPy, PPF)
2. Применение того же `event_mask`, что и в исходных данных (критично)
3. Построение KM ECDF для $X^*$
4. Расчёт $D_b^*$ по формуле Fleming
5. Агрегация $p$-value

**Риск:** Средний. Формула Fleming's modification требует верификации на симулированных данных. Тест: сгенерировать выборку из истинного Weibull_2P, прогнать процедуру, p-value должно быть равномерно распределено на $[0, 1]$.

#### 8.4.2. Profile MLE для трёхпараметрических распределений (Grid + Brent + L-BFGS-B)

**Источник:** [Исследование библиотек, Блок 1] — алгоритмы WeibullR (MLEw3p), EnvStats (elnorm3, egamma3). Ключевая деталь из EnvStats: **репараметризация** $\eta = x_{\min} - \gamma$ делает профиль логарифмической функции правдоподобия более квадратичным вблизи оптимума, что стабилизирует численную оптимизацию.

**Почему вручную:** scipy.stats не имеет встроенного профильного MLE для 3P-распределений. Прямой вызов `fit()` без фиксации `floc` приводит к нестабильным оценкам (попадание в локальные минимумы при $\beta \le 1$). Это задокументировано в [Исследование библиотек, Блок 1]: «scipy.stats.weibull_min без явной фиксации параметра floc приводит к использованию алгоритмов оптимизации общего назначения, которые часто возвращают неадекватные оценки».

**Причина отказа от WeibullR и EnvStats:** оба пакета под GPL. WeibullR — GPL-2, EnvStats — GPL-3. Использование через rpy2 запрещено.

**Реализация:** scipy.optimize.minimize_scalar (Brent) + scipy.optimize.minimize (L-BFGS-B) + NumPy. Архитектура — 5 подзадач (Subtasks A–E, секция 5.7 Методологии 2.0). Репараметризация $\eta = x_{\min} - \gamma$ применяется во всех 3P-распределениях для стабилизации Brent.

**Риск:** Средний. Основной риск — сходимость при $\beta \approx 1$. Mitigation: Subtask A (предварительная проверка $\beta \le 1$) предотвращает вход в зону квази-сингулярности. Grid search (100 точек) гарантирует, что Brent начинает из области, близкой к глобальному максимуму.

#### 8.4.3. Meinshausen correction ($2 \cdot \text{median}(p)$)

**Источник:** [Исследование библиотек, Блок 5] — пакет hdi (GPL-2), статья Meinshausen, Meier & Bühlmann (2009), «P-values for high-dimensional regression», JASA, 101(476), 1361–1372.

**Почему вручную:** hdi распространяется под GPL-2. Использование через rpy2 запрещено.

**Формула:**

$$p_{\text{final}} = \min\!\left(1,\; 2 \cdot \text{median}(p_1, p_2, \dots, p_K)\right)$$

**Реализация:** `np.median(p_values) * 2`. Три строки кода. Источник математики — статья Meinshausen, доступная в открытом доступе (arxiv.org/pdf/1408.4026).

**Риск:** Нулевой. Формула проверена в JASA 2009.

#### 8.4.4. Multi-split валидация (K=100 сплитов)

**Источник:** [Исследование библиотек, Блок 5] — hdi.multi.split. Математическая процедура описана в статье Meinshausen & Bühlmann (2009).

**Почему вручную:** scipy и statsmodels не имеют готовой функции multi-split. Реализация представляет собой цикл из 100 итераций, каждая из которых — стандартный KS-тест.

**Реализация:**
1. 100 независимых сплитов 50/50
2. На каждом: оценка параметров, расчёт $D_k$, вычисление $p_k$ через `scipy.stats.kstwobign.cdf`
3. Meinshausen correction: $p_{\text{final}} = 2 \cdot \text{median}(p_1,\dots,p_{100})$

**Риск:** Низкий. Каждая операция — стандартная.

#### 8.4.5. Jittering

**Почему вручную:** ни одна библиотека не предоставляет именно эту функцию с защитой области определения.

**Формула:** секция 5.6 Методологии 2.0. Реализация — 3 строки NumPy.

**Риск:** Нулевой.

### 8.7. Критический риск и Mitigation

| Риск | Уровень | Mitigation |
|---|---|---|
| scipy версия < 1.11.0 → CensoredData и DKW недоступны | Критический | Явная проверка версии при инициализации (`assert scipy >= 1.11.0`) |
| Parametric bootstrap scipy.goodness_of_fit слишком медленный (GIL) | Средний | Реализуем свой бутстрап на NumPy: векторизованная симуляция + `scipy.optimize.minimize` |
| Fleming's KS: неправильная формула Greenwood's variance | Средний | Unit-тест на симулированных данных (p-value должно быть uniform) |
| Profile MLE: сходимость при β≈1 | Средний | Subtask A предотвращает вход; Grid Subtask B гарантирует глобальный максимум |
| Loglogistic PPF: деление на ноль при u→0 или u→1 | Средний | Защита: `epsilon = 1e-10`; `u_clipped = np.clip(u, epsilon, 1-epsilon)` |

### 8.8. Итоговое заключение

**SciPy является единственным внешним статистическим движком.** Все 12 распределений, оптимизаторы, ECDF, DKW-bands и тесты согласия — реализованы на scipy (BSD/MIT). R-пакеты используются исключительно как **источники математической документации** при реализации вручную. Ни одна GPL-библиотека не используется и не вызывается через межпроцессные мосты.

Все компоненты, которые требуют реализации вручную (Fleming's KS, Profile MLE, Meinshausen, Multi-split, Jittering, TOST), покрываются математическими формулами из верифицированных источников. Ни один компонент не имеет риска «нереализуемо» — для всех есть Mitigation-стратегия, и для всех возможна unit-тестирование на симулированных данных.

### 12.3. Реализация

```python
import matplotlib.pyplot as plt
import numpy as np
from scipy.stats import ecdf

def plot_fit(report: AuditReport, F_frozen, X_test, X_fit=None):
    """Генерация визуализации согласия.
    
    Args:
        report: AuditReport с заполненными полями
        F_frozen: scipy rv_continuous с оценёнными параметрами
        X_test: тестовые данные
        X_fit: опционально — для отображения fit-выборки
    """
    fig, ax = plt.subplots(figsize=(12, 6), dpi=150)
    
    # --- ECDF ---
    ecdf_result = ecdf(X_test)
    ax.step(ecdf_result.cdf.x, ecdf_result.cdf.p,
            where='post', color='tab:blue', linewidth=1.5,
            label='ECDF')

    # --- Theoretical CDF + PDF ---
    x_range = np.linspace(X_test.min() * 0.9, X_test.max() * 1.1, 1000)
    cdf_y = F_frozen.cdf(x_range)
    pdf_y = F_frozen.pdf(x_range)
    ax.plot(x_range, cdf_y, color='tab:red', linewidth=2,
            label=f'{report.distribution} CDF')
    ax.fill_between(x_range, pdf_y / pdf_y.max() * 0.95,
                   alpha=0.15, color='tab:red',
                   label='Fitted PDF (scaled)')

    # --- Shaded deviation (если D_obs > 0.01) ---
    if report.D_obs > 0.01:
        ecdf_interp = np.interp(x_range, ecdf_result.cdf.x, ecdf_result.cdf.p)
        diff = np.abs(ecdf_interp - cdf_y)
        ax.fill_between(x_range, cdf_y - diff, cdf_y + diff,
                        alpha=0.1, color='tab:orange',
                        label=f'|ECDF–CDF|')

    # --- Max deviation marker ---
    max_idx = np.argmax(np.abs(
        np.interp(x_range, ecdf_result.cdf.x, ecdf_result.cdf.p) - cdf_y))
    ax.axvline(x=x_range[max_idx], color='gray',
               linestyle='--', alpha=0.5, linewidth=1)
    
    # --- Annotation ---
    verdict_colors = {
        'ACCEPT': '#d4edda',
        'REJECT': '#f8d7da',
        'ACCEPT_EQUIVALENCE': '#fff3cd',
        'UNDERPOWERED': '#d1ecf1'
    }
    bg = verdict_colors.get(report.verdict, '#ffffff')
    
    annotation = (f"D_obs = {report.D_obs:.4f}\n"
                  f"p_final = {report.p_final:.3f}\n"
                  f"{report.verdict}")
    ax.text(0.98, 0.98, annotation,
            transform=ax.transAxes, fontsize=9,
            ha='right', va='top',
            bbox=dict(boxstyle='round', facecolor=bg, alpha=0.9))

    # --- 3P: threshold ---
    if 'gamma' in report.parameters and report.parameters['gamma'] is not None:
        gamma = report.parameters['gamma']
        ax.axvline(x=gamma, color='tab:orange', linestyle='--',
                   linewidth=1.5, label=f'γ̂={gamma:.0f}')

    # --- TOST: ε-band ---
    if report.branch == 'C_TOST':
        ax.fill_between(x_range,
                        cdf_y - report.epsilon,
                        cdf_y + report.epsilon,
                        alpha=0.1, color='tab:green',
                        label=f'ε-band (ε={report.epsilon})')

    # --- Цензурированные маркеры ---
    # Если event_mask доступен в report — отрисовка маркеров censoring

    # --- Оси и легенда ---
    ax.set_xlabel('x', fontsize=11)
    ax.set_ylabel('Cumulative probability', fontsize=11)
    ax.set_title(
        f'{report.distribution} · N={report.N_test} · '
        f'{report.verdict}',
        fontsize=12, fontweight='bold'
    )
    ax.legend(fontsize=9, loc='upper left')

    # --- Сохранение ---
    plot_dir = Path(f"work/plots/distribution_fit_validator")
    plot_dir.mkdir(parents=True, exist_ok=True)
    plot_path = plot_dir / f"audit-{report.audit_id}.png"
    fig.savefig(plot_path, dpi=150, bbox_inches='tight')
    plt.close(fig)

    report.figure_path = str(plot_path)
    return plot_path
```
