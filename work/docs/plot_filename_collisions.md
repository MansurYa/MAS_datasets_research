# Коллизии имён PNG-плотов в distribution_validator

## Проблема

После полного параллельного прогона `study_runner` (183 studies) в
`work/plots/distribution_validator/` оказалось **91 PNG** вместо ожидаемых
183 (или хотя бы 123 — числа студий, дошедших до `plot_fit`).

## Разбор

После прогона `work/MAS_errors/results.csv` содержит:

| status        | count |
|---------------|------:|
| ACCEPT        |    33 |
| REJECT        |    90 |
| UNDERPOWERED  |    60 |
| **итого**     | **183** |

**Причина 1: UNDERPOWERED не рисует плотов (`main.py:94-113`).**
При режиме `UNDERPOWERED` функция возвращается до строк 173-179, где
вызывается `plot_fit`. `plot_path = ""`, PNG не создаётся. Таких 60 штук.

**Причина 2: имена PNG не уникальны (`visualization.py:191`).**

```python
audit_id = f"audit-{report.dist_type}-N{report.n_test}-{report.verdict}"
```

Имя файла не содержит `study_id`. Разные studies, у которых совпадают
тройки `(final_dist, n_test, verdict)`, пишут в **один и тот же PNG**;
более поздний writer выигрывает, более ранний плот перезатирается.

На полном прогоне 31 коллизия: 123 студии с плотом дали 92 уникальных
имени. На диске остался 91 PNG — один ключ потерян (вероятно, `plot_fit`
бросил исключение в одном из воркеров; ветка `try/except` в
`main.py:177-179` его глушит, `plot_path = ""`).

## Математика

```
183 studies
− 60 UNDERPOWERED (плот не рисуется)
= 123 студии с плотом
− 31 коллизия (несколько studies → один PNG)
− 1 упавший plot_fit
= 91 PNG на диске
```

## Это pre-existing

Баг существовал до параллелизации. Параллельный режим усугубляет
вероятность коллизий: чем больше воркеров, тем чаще writers идут
впритык по времени и последний writer затирает чужие файлы. Но даже
последовательный прогон даёт тот же эффект — имена не уникальны по
дизайну.

## Возможные фиксы (не сделано)

1. **Включить `study_id` в имя файла** (правильный, минимальный фикс):
   ```python
   audit_id = f"audit-{study_id}-{dist_type}-N{n_test}-{verdict}"
   ```
2. **Писать плотов в поддиректорию per-study**
   (`work/plots/distribution_validator/{study_id}/audit-...png`).
3. **Принять текущее поведение** и искать плоты по ключу в
   `results.csv` (`final_dist`+`n_errors`+`status`) — плот
   репрезентативен для всех студий с тем же ключом.

## TL;DR

Плот уникален по `(dist_type, n_test, verdict)`, а не по `study_id`.
При совпадении этих трёх полей у нескольких studies — один PNG на всех.
С добавлением UNDERPOWERED-студий (без плота) и редких падений
`plot_fit` получаем 91 PNG вместо 183.
