# KV Cache Loss — концепция

**KV cache** (Key-Value cache) — механизм оптимизации в трансформерах, при котором вычисленные ключи и значения хранятся в памяти GPU для повторного использования в attention-вычислениях. Это ускоряет inference при длинных контекстах.

---

## Почему теряется KV cache

### 1. Вытеснение по времени (Time-based Eviction)

При длительных перерывах (>30 минут) между запросами система освобождает память для других задач. KV cache вытесняется из VRAM.

### 2. Вытеснение по объёму (Capacity-based Eviction)

Когда достигается лимит памяти GPU, старые записи cache вытесняются. В мультиарендных системах (shared GPU clusters) это происходит при высокой нагрузке.

### 3. Миграция между устройствами

При перемещении запроса на другой GPU (preemption, re-scheduling) cache теряется, так как привязан к конкретному устройству.

---

## Влияние на производительность

| Метрика | С hot cache | После cache loss |
|---------|-------------|------------------|
| Latency | Низкая | Высокая |
| Input tokens processed | Cache read | Все заново |
| Cache hit ratio | >0.9 | 0 |

**Ключевой эффект:** При cache loss модель вынуждена заново обрабатывать все previous tokens, что увеличивает latency и стоимость.

## Определение в данных Claude Code Usage

### Источник: `datasets/claude_code_usage_kv_cache_loss.csv`

Столбцы:
- `Cache Read Tokens` — сколько токенов прочитано из кеша
- `Cache Creation Tokens` — сколько токенов записано в кеш
- `Time` — время запроса

### Критерии события

Событие KV cache loss регистрируется когда:
1. Интервал с предыдущего запроса > 30 минут
2. `Cache Read Tokens = 0` (нет попаданий)
3. Предыдущий шаг в сессии имел `Cache Read Tokens > 100`

**Логика:** До перерыва модель активно читала из кеша (>100 токенов) — значит кеш был "горячим". Если после перерыва `Cache Read = 0`, а предыдущий шаг имел горячий кеш — это вытеснение.

### Тёплые vs холодные сессии

**Тёплая сессия:** хотя бы один запрос имеет Cache Read Tokens > 0. Таких 68 из 86.

**Холодная сессия:** все запросы имеют Cache Read Tokens = 0. Таких 18 (849 запросов).

Холодные сессии не используют cache — для них cache_loss не применим.

## Статистика из Claude Code Usage

| Метрика | Значение |
|---------|----------|
| Сессий (всего) | 86 |
| Тёплых сессий | 68 |
| Запросов в тёплых | 6712 |
| KV cache loss событий | 23 |
| P(loss / request) | 0.34% |
| P(loss / after_gap) | 34.3% |

**34.3%** — вероятность cache loss после перерыва > 30 минут в тёплых сессиях. Это высокий показатель, указывающий на агрессивное управление памятью или shared GPU infrastructure.

## Как использовать в симуляторе

В симуляторе динамической доступности (MAS) KV cache loss моделируется как:

1. **Событие** с вероятностью ~0.34 после интервала > 30 мин (для тёплых сессий)
2. **Эффект:** увеличение latency на T_reeval = время на повторное вычисление attention
3. **Домен:** влияет на любой запрос к LLM после простоя в тёплых сессиях

### Параметры для fault injection

```python
KV_CACHE_LOSS_PROB_AFTER_GAP = 0.343  # P(loss | gap > 30min, warm sessions)
KV_CACHE_LOSS_PROB_PER_REQUEST = 0.0034  # P(loss | any request, warm sessions)
```
