Третье задание в серии. Предыдущие результаты:

**Цель:** Собрать единую агрегированную таблицу всех ошибок из всех источников, присвоить каждой класс моделирования 1–4.

## Задача 1. Извлечь статистику из ноутбука TRAIL

Найти файл `p1_fault_mode_distributions.ipynb`. Запустить его или прочитать как JSON и извлечь из output-ячеек следующие данные по каждой ошибке TRAIL:
- название ошибки
- n (число наблюдений)
- p̂ (вероятность)
- ci_lower, ci_upper (доверительный интервал)
- источник датасета

Если ноутбук не запускается — прочитать его как JSON (`json.load`) и извлечь текстовые outputs из ячеек.

---

## Задача 2. Составить мастер-список ошибок

Взять за основу таблицу из `fault_mode_analysis_and_classification_ru`. Добавить к ней категории из AgentRx/Who&When, которых там нет. Результат — единый список ошибок без дублей.

Для каждой ошибки заполнить поля:

| Поле | Описание |
|---|---|
| `error_id` | Уникальный ID (snake_case, например `kv_cache_loss`) |
| `name_en` | Название на английском |
| `name_ru` | Название на русском |
| `description` | 1–2 предложения что это такое |
| `sources` | Через запятую: trail, agentRx, who_and_when |
| `trail_category` | Ближайшая TRAIL категория (если есть) |
| `agentRx_category` | Ближайшая AgentRx категория (если есть) |
| `modeling_class` | 1, 2, 3 или 4 |
| `modeling_class_reason` | 1–2 предложения обоснования |

---

## Задача 3. Присвоить классы моделирования

Использовать следующие определения:

- **Класс 1** — невозможно моделировать: ошибка требует прогона реального LLM (галлюцинации, неверный код, неправильное рассуждение)
- **Класс 2** — моделируется напрямую: можно воспроизвести через изменение IR-графа или параметров блоков без статистических допущений
- **Класс 3** — моделируется статистически: описывается вероятностью и распределением, инжектируется как случайное событие
- **Класс 4** — моделируется, но нецелесообразно: технически возможно, но выходит за рамки проекта (долгосрочная деградация, специфика железа)

---

## Задача 4. Агрегировать статистику

Для каждой ошибки собрать статистику из всех доступных источников в одну строку:

| Поле | Описание |
|---|---|
| `trail_n` | n из TRAIL (0 если нет) |
| `trail_p` | вероятность из TRAIL |
| `trail_ci_lower`, `trail_ci_upper` | CI из TRAIL |
| `agentRx_n` | n из AgentRx |
| `agentRx_p` | вероятность из AgentRx |
| `agentRx_ci_lower`, `agentRx_ci_upper` | CI из AgentRx |
| `who_and_when_n` | n из Who&When |
| `who_and_when_p` | вероятность из Who&When |
| `who_and_when_ci_lower`, `who_and_when_ci_upper` | CI из Who&When |
| `total_n` | сумма по всем источникам |
| `sufficient_data` | True если total_n ≥ 20 |

Если для ошибки нет данных из источника — ставить `null`.

## Результаты

**`data/aggregated_errors.csv`** — полная таблица: все поля из задач 2–4 в одном файле, одна строка на ошибку.

**`docs/tz3_aggregated_table_report.md`** — отчёт со следующими разделами:

1. **Сводная таблица** (компактная): `error_id | name_en | modeling_class | total_n | sufficient_data | sources`

2. **Таблица по классам** — для каждого класса 1–4 список ошибок с обоснованием

3. **Статистика по источникам** — для каждой ошибки: p̂ и CI по каждому источнику отдельно

4. **Выводы**: какие ошибки классов 2–3 имеют sufficient_data=True и готовы к анализу распределений в ТЗ №4
