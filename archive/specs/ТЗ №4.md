## Задача 2. Посчитать P(сообщение)

P(сообщение) — вероятность того, что случайный шаг траектории содержит данную ошибку:

```
P(сообщение) = n_failures / total_steps_across_all_trajectories
```

**Для AgentRx:**
- Загрузить `magentic_dataset.jsonl` и `tau_retail_dataset.jsonl` (файлы с траекториями, без аннотаций)
- Для каждой траектории посчитать число шагов: `len(steps)`
- `total_steps` = сумма по всем траекториям
- Для каждой категории: `P(сообщение) = n_failures_in_category / total_steps`

**Для Who&When:**
- Загрузить Parquet файлы
- Длина траектории = максимальный `mistake_step` + 1 (если нет другого поля с длиной)
- Если есть поле `history` — посчитать `len(history)` как длину траектории
- `total_steps` = сумма длин всех траекторий

Посчитать Wilson 95% CI для P(сообщение) аналогично P(траектория).

## Задача 3. Анализ распределения по шагам

Только для ошибок с n≥20: `guardrails_triggered` (AgentRx, n=23) и `tool_web_failure` (Who&When, n=25).

Для каждой:

**3a. Описательная статистика позиций ошибок:**
mean, median, std, min, max, p25, p75, p90, p95

**3b. Гистограмма:**
Построить гистограмму позиций ошибок (step_number / mistake_step). Сохранить как PNG в `data/plots/hist_{error_id}.png`.

**3c. Попытка подгонки распределений:**
Попробовать подогнать: Exponential, Weibull(2 параметра), LogNormal.

Для каждого распределения:
- Оценить параметры через MLE (`scipy.stats.*.fit`)
- Провести KS-тест (`scipy.stats.kstest`)
- Записать: distribution, params, ks_statistic, ks_pvalue

**Явное предупреждение в коде и отчёте:** при n<100 результаты подгонки ненадёжны. При n<3000 нельзя делать уверенных выводов о виде распределения. Все результаты подгонки помечать как `low_confidence=True`.
