**ТЗ №1 — Разведка источников данных**

---

**Цель:** Понять что именно можно извлечь из каждого источника данных, прежде чем писать парсеры.

---

**Шаг 1. Прочитать существующую классификацию**

Найти файл `fault_mode_analysis_and_classification_ru` (может быть `.docx`, `.md` или `.txt`). Извлечь из него полный список ошибок в виде таблицы:

| Название ошибки (EN) | Название (RU) | Категория моделирования | Датасеты упомянуты |

---

**Шаг 2. Детальный анализ Who&When и AgentRx**

Это основные источники типизированных ошибок. Для каждого:

*Who&When:*
- Загрузить все файлы (Parquet + JSON)
- Вывести схему полей
- Для полей `mistake_reason`, `failure_category`, `mistake_agent`, `root_cause` — вывести **все уникальные значения** с частотами
- Показать 2 полных примера записи

*AgentRx:*
- Загрузить все 4 JSONL файла
- Для каждого файла вывести схему
- Для полей `failure_category`, `failed_agent`, `root_cause` — вывести **все уникальные значения** с частотами
- Показать 1 полный пример записи из каждого файла

---

**Шаг 3. Быстрая проверка остальных 5 датасетов**

Для каждого из: nebius, SWE-Gym, terminalbench, ITBench, Mind2Web-Live:
- Загрузить **первые 3 записи**
- Вывести все поля верхнего уровня с типами
- Проверить наличие полей со словами: `error`, `failure`, `fault`, `fail`, `mistake`, `issue`, `exception`, `resolved`, `exit_status`, `category`, `reason`, `status`
- Если такие поля есть — вывести все уникальные значения
- Если ошибки спрятаны внутри вложенных структур (`trajectory`, `messages`, `steps`) — заглянуть на 1 уровень вглубь и показать пример одного шага

Для больших датасетов (nebius — 80k записей) — **не загружать всё**, достаточно первых 5 записей.

---

**Шаг 4. Итоговый вывод**

В конце отчёта написать раздел `## Вывод`:

Для каждого датасета одной строкой:
- Есть ли явная типизация ошибок (да/нет)
- Если да — какие поля и сколько уникальных типов
- Если нет — что максимум можно извлечь (exit_status, длина траектории, текст)
