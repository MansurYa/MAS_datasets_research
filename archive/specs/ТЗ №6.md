## Часть C. Методологический документ

Файл: `report/methodology.md` — краткий, на русском. БЕЗ таблиц с цифрами из CSV. БЕЗ дублирования статистики. Только методология.

### Структура:

**1. Источники данных** — таблица датасетов (название, число траекторий, тип разметки, особенности). БЕЗ статистики ошибок.

**2. TRAIL: маппинг категорий** — из какого поляTRAIL в какой error_id. Таблица: TRAIL_category → our_error_id → n_annotations. Это ключевая информация которая не сохранится в CSV.

**3. Who&When: ключевые слова** — для каждой категории список ключевых слов по которым классифицировали. Это методология, не данные.

**4. Keyword search: словари** — какие ключевые слова для каких датасетов и категорий. Оценка надёжности (высокая/низкая).

**5. Определения** — формальные определения всех метрик и терминов:
- P(траектория), P(сообщение), Wilson CI, KS-тест, insufficient_data
- Классы моделирования 1–4 с примерами
- Правило fit_conclusion: когда какое писать
- Почему порог insufficient_data = n < 20

**6. Ограничения** — список:
- TRAIL: только GAIA + SWE-bench, поведение может отличаться в production
- Keyword search: ложные срабатывания (числа как код, имена классов)
- Who&When HC: 58 записей из 184, keyword matching покрытие ~71%
- KS-тест при малом n: слепой, p-value завышен
- Бимодальные распределения: KS-тест не различает
