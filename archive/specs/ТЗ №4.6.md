## Задача 1. Извлечь позиции ошибок

Для каждой надёжной пары (категория × датасет) пройти по траекториям и найти номер шага первого вхождения ключевого слова.

**nebius** (Parquet, поле `trajectory` — список шагов с `role` и `text`):
- Искать только в шагах где `role == "user"`
- Для каждой траектории: найти индекс первого шага с ключевым словом → это `first_occurrence_step`
- Также записать `trajectory_length` = общее число шагов в траектории

**ITBench** (session.jsonl файлы):
- Для каждого файла: найти первую запись с ключевым словом в `payload`
- `first_occurrence_step` = порядковый номер этой записи среди всех записей файла

**terminalbench** (Parquet, поле `steps` — строка JSON или текст):
- Распарсить `steps`, найти первый шаг с ключевым словом
- `first_occurrence_step` = индекс этого шага

Результат: для каждой траектории с ошибкой — пара (`first_occurrence_step`, `trajectory_length`).

## Задача 2. P(сообщение)

Для каждой надёжной пары:

```
P(сообщение) = n_total_occurrences / total_steps_across_all_trajectories
```

- `n_total_occurrences` — суммарное число шагов с ключевым словом по всем траекториям
- `total_steps` — сумма длин всех траекторий в датасете

Wilson 95% CI. Явное предупреждение: шаги внутри траектории не независимы (кластерная структура), CI занижен.

## Задача 3. Описательная статистика позиций

Для каждой надёжной пары — две версии:

**Абсолютная позиция:** `first_occurrence_step` как есть.

**Нормализованная позиция:** `first_occurrence_step / trajectory_length` → [0, 1].

Для каждой: mean, median, std, min, max, p25, p75, p90, p95, n.

Переиспользовать функцию `step_stats()` из `tz4_distributions.py`.

## Задача 5. Подгонка распределений

Для каждой надёжной пары — подогнать: Exponential, Weibull(2 параметра), LogNormal, и для нормализованной — дополнительно Beta и Uniform.

MLE через `scipy.stats.*.fit()`. KS-тест через `scipy.stats.kstest`.

**Ключевое отличие от ТЗ №4:** здесь n >> 3000 для nebius-категорий. При таком n KS-тест имеет высокую мощность — отвержение H0 (p < 0.05) теперь информативно и означает что распределение не подходит. Это нужно явно указать в отчёте.

Для ITBench (n=80) и terminalbench (n~1750) — предупреждение о низкой мощности теста как в ТЗ №4.

Переиспользовать функцию `fit_distributions()` из `tz4_distributions.py`.

Поле `best_distribution`: распределение с наибольшим KS p-value (лучшая подгонка).
