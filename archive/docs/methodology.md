## 3. Who&When: ключевые слова для hand-crafted классификации

Из 58 записей Who&When с hand-crafted привязкой к шагу использовались ключевые слова и паттерны, определяющие категорию. 46 записей получили ненулевую категорию, 12 отнесены к unclassified. Это методология, а не данные.

**Ключевые слова и паттерны по категориям:**

- `code_error`: "incorrect", "wrong", "error in code", "syntax error", "bug in", "the code is", "Python code is", "executed it returns no output"
- `factual_error`: "incorrect fact", "wrong assumption", "asserted without evidence", "did not check", "misremembered"
- `hallucination`: "made up", "fabricated", "invented", "not in the data", "not in the source", "does not exist in the conversation"
- `orchestration_failure`: "wrong agent", "assigned to wrong", "should have been", "routing", "step 2 instead of", "incorrect agent selection"
- `resource_abuse`: "step limit", "exhausted the", "too many attempts", "repeatedly", "loop", "no progress after", "exceeding"
- `tool_web_failure`: "HTTP", "404", "403", "500", "connection refused", "network error", "URL", "API"
- `unclassified`: всё остальное, что не попало ни под одну категорию

## 4. Keyword search: словари и надёжность

Для поиска ошибок в текстах траекторий без экспертной аннотации использовались словари ключевых слов. Это даёт верхнюю оценку частоты — возможны ложные срабатывания.

### 4.1 tool_web_failure (HTTP-ошибки)

- **Словарь:** `404`, `403`, `500`, `502`, `503`, `connection refused`, `connection error`, `network error`, `failed to connect`, `no route to host`, `name resolution failed`, `dns`
- **Надёжность:**
  - Nebius — **высокая**. Реальные HTTP-ошибки внешних API.
  - ITBench — **высокая**. SRE-задачи явно описывают HTTP 500 как симптом.
  - SWE-Gym — **низкая**. Числа 403/404/500 — номера строк кода, константы, docstrings.
  - TerminalBench — **низкая**. 500 и 5000 — размеры выборок, не HTTP-коды.

### 4.2 resource_not_found (Файл не найден)

- **Словарь:** `filenotfounderror`, `no such file`, `not found`, `does not exist`, `cannot find`, `path does not exist`
- **Надёжность:**
  - Nebius — **высокая**. Реальные ошибки файловой системы.
  - ITBench — **высокая**. `No such file or directory`, отсутствие полей.
  - TerminalBench — **средняя**. Реальные ошибки вперемешку с рассуждениями агента ("R not found yet, checking apt").
  - SWE-Gym — **средняя**. Есть `not found` в docstrings и комментариях.

### 4.3 tool_timeout (Таймауты)

- **Словарь:** `timeout`, `timed out`, `deadline exceeded`, `request timeout`, `operation timed`
- **Надёжность:**
  - ITBench — **высокая**. Реальные таймауты shell-команд (exit_code 124).
  - Nebius/SWE-Gym — **низкая**. `timeout` в именах тестов (`test_timeout.py`), в конфигах.
  - TerminalBench — **средняя**. Реальные таймауты установки пакетов, но также рассуждения агента.

### 4.4 permission_error (Ошибки доступа)

- **Словарь:** `permission denied`, `access denied`, `permissionerror`, `not permitted`, `operation not permitted`
- **Надёжность:**
  - TerminalBench — **высокая**. Реальные отказы в правах доступа.
  - Nebius — **низкая**. `permission denied` в исходном коде — агент читает обработчик ошибок, а не сам получает её.
  - SWE-Gym — **средняя**. Смесь реальных и кода с `PermissionError`.

### 4.5 memory_error (OOM)

- **Словарь:** `memory error`, `out of memory`, `oom`, `killed`, `cannot allocate`, `memory limit`
- **Надёжность:**
  - TerminalBench — **высокая**. Реальные OOM-убийства процессов.
  - Остальные датасеты — **средняя**. `killed` в логах, но не всегда OOM.

## 5. Определения

### 5.1 P(траектория)

Вероятность того, что траектория содержит хотя бы одно вхождение данной ошибки:

```
P(траектория) = n_trajectories_with_error / n_trajectories_total
```

Для каждой вероятности рассчитывается **Wilson 95% доверительный интервал**.

### 5.2 Wilson 95% CI

Для пропорций с малыми выборками используется поправка Уилсона:

```
θ̂ = (p̂ + z²/2n) / (1 + z²/n)
z = 1.96 (для 95%)
CI = [θ̂ - Δ, θ̂ + Δ]
Δ = z * √(p̂(1-p̂)/n + z²/4n²) / (1 + z²/n)
```

### 5.3 KS-тест и fit_conclusion

Для оценки качества подгонки распределения (Exponential, Weibull, LogNormal, Beta, Gamma, Lomax) используется одновыборочный критерий Колмогорова-Смирнова. Решение принимается по **приоритету правил** (сверху вниз):

| Приоритет | Условие | fit_conclusion |
|---|---|---|
| 1 | n < 100 или NaN | `недостаточно данных` |
| 2 | KS p-value < 0.05 | `параметрическое не подходит` |
| 3 | n ≥ 3000, KS p-value ≥ 0.05 | `подгонка найдена` |
| 4 | KS p-value ≥ 0.05 | `подгонка формально не отклонена` |
| — | KS p-value = NaN | `недостаточно данных` |

Приоритет 2 означает: если данных формально достаточно (n ≥ 100), но KS-тест отклоняет распределение (p < 0.05) — результат всё равно `параметрическое не подходит`. Правило «p < 0.05» действует независимо от n.

### 5.4 Достаточность данных (3 состояния)

`insufficient_data` в CSV — текстовое поле, **не** бинарный флаг. Три состояния:

| Условие | Значение | Следствие |
|---|---|---|
| n < 100 или NaN | `недостаточно` | CI слишком широкие; KS-тест слепой; подгонка бессмысленна |
| 100 ≤ n < 3000 | `частично` | Базовые статистики надёжны; подгонка формально не отклонена, но без достаточных оснований |
| n ≥ 3000 | `достаточно` | Подгонка распределения обоснована: KS p-value ≥ 0.05 → `подгонка найдена` |

> Ранее использовался бинарный флаг с порогом n < 20. Переход на три состояния с порогами n=100 / n=3000 даёт более консервативную и честную оценку.

### 5.5 Классы моделирования

**Класс 1 — Невозможно моделировать.**
Ошибки, требующие полного прогона весов LLM для воспроизведения. Даже при наличии статистики — в симуляторе без запуска модели невозможно.
*Примеры:* галлюцинация, неверная интерпретация результата, сбой оркестрации, код содержит логическую ошибку.

**Класс 2 — Моделируется напрямую.**
Ошибки, воспроизводимые через изменение структуры IR-графа или параметров блоков без статистических допущений.
*Примеры:* потеря KV-кэша (удаление кэшированного состояния блока), превышение пропускной способности канала, достижение лимита контекстного окна.

**Класс 3 — Моделируется статистически.**
Ошибки, которые нельзя воспроизвести напрямую, но можно описать вероятностно: взять датасет, оценить P(траектория), подобрать распределение шага и по нему генерировать события.
*Примеры:* таймаут внешнего вызова, ошибка доступа к веб-ресурсу, исчерпание ресурсов на уровне шага.

**Класс 4 — Моделируется, но нецелесообразно.**
Ошибки, технически реализуемые, но не имеющие смысла в контексте проекта (горизонт симуляции, масштаб кластера, отсутствие данных).
*Примеры:* деградация оборудования на длинном горизонте, троттлинг GPU в крупных кластерах, коррелированные сбои SSD.

## 6. Ограничения

1. **TRAIL ограничен GAIA + SWE-bench.** Поведение агентов в production может существенно отличаться от лабораторных бенчмарков; доменная специфика влияет на распределение ошибок.

2. **Keyword search даёт завышенные оценки.** Числа в текстах (номера строк `403`, константы `5000`) ложно срабатывают как HTTP-коды. Для Nebius/ITBench эффект умеренный, для SWE-Gym/TerminalBench — значительный.

3. **Who&When HC: покрытие ~71%.** Из 184 записей hand-crafted-классификация применена к 58. Остальные либо не содержат привязки к шагу, либо не попали под ключевые слова.

4. **KS-тест при малом n — слепой.** При n < 100 p-value всегда высокое (слабая мощность), что создаёт иллюзию хорошей подгонки. Правило n ≥ 100 частично компенсирует это.

5. **Бимодальные распределения KS-тест не различает.** Одномодальное и бимодальное распределение могут дать одинаковый p-value. Визуальный контроль гистограмм обязателен.

6. **AgentRx категории частично пересекаются.** Например, `instruction_adherence_failure` и `intent_plan_misalignment` в данных tau_retail/magentic_one могут описывать похожие ситуации; унификация требует экспертной проверки.
